# ICMP·ARP와 응용 프로토콜

<div class="summary">

- **네트워크 계층(인터넷 계층)** 프로토콜: IP, **ICMP**, **IGMP**, **ARP**, **RARP**. **응용 계층**: SMTP, SNMP, FTP, TFTP, HTTP(S), DNS, Telnet, SSH, DHCP.
- **ARP**는 IP → MAC(물리 주소), **RARP**는 MAC → IP, **DHCP**는 IP 자동 할당, **ICMP**는 오류 보고와 진단(ping), **IGMP**는 멀티캐스트 그룹 관리입니다.
- **포트**: HTTP 80, **HTTPS 443**, SMTP 25, SSH 22, Telnet 23, FTP 20/21, **SNMP 161**, **SNTP 123**, DNS 53.
- **UDP 기반**: TFTP, SNMP, DHCP, DNS(질의). **TCP 기반**: FTP, Telnet, SMTP, HTTP(S), SSH.
- **라우팅 프로토콜**: OSPF(링크 스테이트, Dijkstra), RIP(거리 벡터), BGP·EGP·IDRP(AS 사이).

</div>

## 1. ARP와 RARP

| | 방향 | 설명 |
|---|---|---|
| **ARP** | **IP 주소 → 물리(MAC) 주소** | 이더넷의 **브로드캐스트**로 목적지 IP에 물리 주소를 매핑 |
| **RARP** | **물리 주소 → IP 주소** | RFC 903. RFC 951의 BOOTP에 의해 **대체**되는 중. 디스크가 없는 장치가 자기 IP를 알아낼 때 사용. 이더넷, FDDI, 토큰 링에서 사용 가능 |

**ARP 동작 순서** (`ping 210.223.112.9`를 했을 때): **ARP Cache 확인 → ARP Broadcast → 자체 IP와 일치 여부 확인(수신 측) → ARP Reply 발송**.

**ARP 캐시**
- 각 시스템이 IP-MAC 대응을 **일정 시간 보관**합니다.
- 등록된 주소는 **생존 시간(TTL)** 을 가지고, 일정 시간(예: 1-2분) 안 쓰이면 삭제될 수 있습니다.
- 일부 시스템은 재사용할 때 TTL을 초기값으로 되돌립니다.
- 캐시가 있으므로 통신할 때마다 **매번** MAC 주소를 다시 요청하지 않습니다.
- ARP 캐시는 IP와 **MAC** 주소를 매핑하며 도메인 주소는 다루지 않습니다.

> **함정** ARP는 **수신 측의 IP는 알고 MAC을 모를 때** 브로드캐스트를 씁니다(IP를 모를 때가 아닙니다). 동적으로 설정된 항목을 정적으로 바꾸는 옵션은 `-d`가 아니라 `-s`(추가)이며, `-d`는 삭제입니다.

## 2. ICMP

IP 데이터그램을 처리하는 동안 생기는 **오류를 보고**하고 네트워크 진단(질의 메시지)을 하는 프로토콜입니다. 호스트의 **물리 주소를 제공하지 않습니다**(ARP의 일). **호스트의 IP 중복**은 ICMP 메시지 내용이 아닙니다.

| 타입 | 메시지 |
|---|---|
| **0** | Echo Reply (에코 응답) |
| **3** | Destination Unreachable (목적지 도달 불가) |
| **4** | Source Quench (**흐름제어·폭주제어**) |
| **5** | Redirect (경로 재지정, 라우터가 호스트에게 알림) |
| **8** | **Echo Request** (에코 요청) |
| **11** | Time Exceeded (시간 초과, TTL이 0이 되어 삭제될 때) |
| **13** | Timestamp Request |
| **17** | Address Mask Request (서브넷 마스크 요구) |

> **함정** Echo Request는 **8번**, Echo Reply는 **0번**입니다. 5번(Redirect)이나 3번(Destination Unreachable)을 Echo Request라고 하면 틀립니다.

> **함정** ICMP는 "비대칭 프로토콜이고 TTL을 제공한다"는 설명이 **틀린** 문장으로 출제됩니다. ICMP 메시지에는 질의 메시지가 있고, 반향(Echo)과 회답 메시지로 호스트 간 연결 확인을 지원합니다.

**ping**: ICMP 기반의 진단 도구입니다. Echo Request를 보내고 Echo Reply를 기다려 TCP/IP **연결성**을 테스트하고 **RTT**(왕복 지연 시간)를 측정합니다. 오류를 **정정해 주지는 않으며**, TCP/IP 구성 파라미터(IP 설정)를 확인하는 것은 `ipconfig`의 일입니다.

**ICMPv6**에서 IPv4의 ARP 역할과 도달 가능 여부 검사는 **이웃 요청과 광고 메시지**(Neighbor Solicitation and Advertisement)가 합니다.

## 3. IGMP

| 항목 | 내용 |
|---|---|
| 역할 | 로컬 네트워크에서 **멀티캐스트 그룹의 멤버십을 관리** (호스트가 그룹을 인근 라우터에 알림) |
| 계층 | 네트워크 계층(L3), OSI 4계층이 아님 |
| 구조 | 호스트와 라우터 간의 **비대칭** 통신, **TTL 제공** |
| 적합한 용도 | **멀티캐스팅** (유니캐스트에는 부적합) |
| 예 | 스트리밍에서 채널을 바꿀 때 그룹 가입·탈퇴 신호 |

> **함정** IGMP는 오류 보고(ICMP), 대용량 파일 전송, 물리 주소 안내(ARP)와 구별합니다. IGMPv1은 첫 보고 메시지가 손실되어도 재전송하지 않습니다.

## 4. DHCP

| 항목 | 내용 |
|---|---|
| 역할 | 클라이언트에게 **IP 주소를 자동 할당**. 주소 관리가 쉽고 **사용자가 자주 바뀌는 환경**(학교)에 유용 |
| 할당 방식 | **수동 할당(Manual)**, **자동 할당(Automatic)**, **동적 할당(Dynamic)** (우선순위 할당은 없음) |
| 적합한 장비 | 교육장용 **PC** |
| 부적합한 장비 | **웹 서버**처럼 영구적인 IP가 필요한 장비(고정 IP 사용), 일반적으로 AP, 네트워크 프린터도 고정이 편함 |
| 관련 | BOOTP(RARP의 후속 개념) |

> **함정** "영구적인 IP가 필요한 웹 서버에 동적 주소를 제공"하는 것은 DHCP의 **장점이 아닙니다**. 부팅 때 MAC 주소를 기반으로 IP를 자동 부여받는 기술을 묻는 문제의 답은 DHCP입니다.

## 5. DNS

| 항목 | 내용 |
|---|---|
| 역할 | 도메인 이름 → IP 주소 변환. 계층적 호스트 이름을 쓰는 **분산 데이터베이스** |
| 호스트 이름 | 영문자, 숫자, 하이픈(-)으로 구성 (`@`, `#` 같은 특수 문자는 쓸 수 없음) |
| 캐싱 | 이전에 접근한 도메인-IP 대응을 저장 |
| 로드 밸런싱 | 하나의 도메인에 여러 IP를 두고 번갈아 반환하는 방식으로 부하 분산 가능 |
| 성격 | **방화벽 같은 보안 장비가 아님** |
| 포트 | 53, **TCP와 UDP 모두** 사용 |
| 로컬 설정 | DNS 서버가 없는 환경에서는 **`/etc/hosts`** 파일을 수정해 로컬 DNS처럼 사용 |

**TTL(DNS)**: 데이터가 DNS 서버의 **캐시에서 만료되기까지 남은 시간**입니다. IP 패킷의 TTL(홉 수)과 다릅니다. 패킷이나 존(zone)과는 관계가 없습니다.

**질의 방식**: 클라이언트가 캐싱 네임서버에 질의하면, 서버가 루트 → `kr` → `or.kr` → `icqa.or.kr` 순서로 대신 질의해 최종 IP를 알려 주는 과정은 **재귀적 질의**로 출제되었습니다.

### 레코드

| 레코드 | 의미 |
|---|---|
| **A** | 호스트 이름 → IPv4 주소 |
| **AAAA** | 호스트 이름 → IPv6 주소 |
| **PTR** | **역방향 조회** (IP → 이름) |
| **SOA** | **존 파일의 첫 번째 레코드**. 도메인 이름 필드와 **시리얼 값**(영역 파일 갱신 여부 확인) |
| MX | 메일 서버 |

## 6. 메일 프로토콜

| 프로토콜 | 역할 |
|---|---|
| **SMTP** | **전자 우편 송신**(전송), 포트 25 |
| **POP3** | 서버에서 메일을 **내려받아** 확인(보통 내려받은 뒤 서버에서 삭제하는 방식), 수신 |
| **IMAP** | 메일을 **서버에 그대로 두고** 여러 기기에서 접근·검색 |

> **함정** POP3와 IMAP의 특성을 서로 바꾼 설명이 틀린 문장으로 나옵니다. "서버에 두고 여러 기기에서 동기화"는 IMAP입니다. POP3는 메일 시스템과 관련 있는 프로토콜이며, 송수신이 동시에 처리되는 것도, 둘 다 실시간 동기화하는 것도 아닙니다.

## 7. 파일 전송: FTP와 TFTP

| | FTP | TFTP |
|---|---|---|
| 의미 | File Transfer Protocol | **Trivial** File Transfer Protocol |
| 전송 | **TCP** (3-way) | **UDP**, 신속하고 단순 (손실 가능성이 단점) |
| 포트 | 제어 21, 데이터 20 | 69 (25번이 아님) |
| 접속 | 계정 접속과 익명(anonymous) | |
| 암호화 | 없음 (FTPS는 FTP에 보안을 더한 것, SFTP는 SSH 기반) | |

**FTP 데이터 채널**: 서버가 Well-known 포트 **20번**으로 데이터 채널 연결을 시도합니다. 파일 송수신 요구가 있을 때마다 새로 설정되고 끝나면 즉시 해제됩니다. 제어용은 21번입니다.

> **함정** FTP가 UDP를 쓰거나 69번 포트로 전송한다는 설명은 틀립니다. TFTP가 UDP 69번이고, "3방향 핸드셰이킹 TCP 세션"으로 전송한다는 설명도 TFTP에 틀립니다.

## 8. 원격 접속: Telnet과 SSH

| | Telnet | SSH |
|---|---|---|
| 포트 | TCP **23** | TCP **22** |
| 보안 | 평문 | 데이터 **암호화**, **무결성** 제공, **공개키 암호화** 사용 |
| 플랫폼 | | 리눅스·유닉스 외에 **윈도 등에서도 사용 가능** |
| 버전 | | SSH-1은 RSA 암호화, SSH-2는 RSA 외 더 다양한 키 교환 방식 지원 |

스위치 원격 접속을 Telnet에서 SSH로 바꾸는 이유는 보안입니다. SSH가 TCP 23번을 쓴다는 설명은 틀립니다.

## 9. 웹: HTTP와 HTTPS

| | HTTP | HTTPS |
|---|---|---|
| 포트 | **TCP 80** | **TCP 443** |
| 보안 | 평문 | **TLS(SSL)** 로 응용 계층 데이터를 암호화·보호, 서버 신원을 인증서로 검증 |

> **함정** HTTPS가 udp/443이거나 tcp/80을 쓴다는 설명, 인증이 필요 없다는 설명은 틀립니다.

| HTTP 버전 | 설명 |
|---|---|
| HTTP/2 | SPDY 기반, **TCP** 연결 사용 |
| HTTP/3 | **QUIC** 기반, **UDP** 사용 (TCP가 아님) |

| 상태 코드 | 뜻 |
|---|---|
| 200 | OK |
| 203 | Non-Authoritative Information |
| 400 | Bad Request |
| **403** | **Forbidden** (요청이 서버에 의해 거부됨, 접근 권한 없음) |

## 10. 네트워크 관리와 시간 동기화

**SNMP**

| 항목 | 내용 |
|---|---|
| 역할 | 네트워크 장비의 **관리 및 감시**. 응용 계층 표준 프로토콜(RFC 1157) |
| 구성 | 관리 시스템의 **Manager**와 관리 대상 장비의 **Agent**. Manager가 Agent의 상태를 조회하거나 설정을 변경 |
| 전송 | **UDP**, 포트 **161** (181도 143도 아님) |
| 방식 | 주기적 **폴링**으로 정보를 수집해 확장이 쉽지만 트래픽이 늘 수 있음 |
| 보안 | SNMPv2c는 암호화·인증을 기본으로 제공하지 않음 |

**SNTP**: 라우터와 스위치의 **시간 동기화**에 쓰고 포트 **123**입니다.

**프록시(Proxy)**: 클라이언트가 자신을 통해 다른 네트워크 서비스에 **간접 접속**하게 하는 컴퓨터나 응용 프로그램입니다. 서버와 클라이언트 사이에서 **대리 통신**하고 **캐시**로 트래픽을 줄이고 전송 시간을 단축합니다.

## 11. 라우팅 프로토콜

| 프로토콜 | 특징 |
|---|---|
| **OSPF** | AS **내부**, **링크 스테이트** 방식, 자신의 상태를 이웃에게 알림, **Dijkstra** 알고리즘, Hello 패킷, 같은 비용의 여러 경로 가능 |
| RIP | 거리 벡터, 30초 주기 갱신 |
| EGP, BGP, IDRP | **AS 사이**의 라우팅 |

> **함정** OSPF의 기본 알고리즘은 **Dijkstra**입니다. Bellman-Ford와 거리 벡터 알고리즘은 RIP 쪽입니다.

## 12. 계층 분류와 기타

| 분류 | 프로토콜 |
|---|---|
| 응용 계층 | SMTP, SNMP, TFTP, FTP, HTTP, DNS, Telnet |
| **네트워크 계층** | **ICMP**, **IGMP**, ARP, RARP, IP |
| 전송 계층 | TCP, UDP |

> **함정** 같은 계층이 아닌 것을 고르는 문제에서 SMTP는 응용 계층이고 RARP, ICMP, IGMP는 네트워크 계층이므로 **SMTP**가 정답입니다. 응용 계층이 아닌 것을 고를 때는 **ICMP**입니다.

**캡슐화(Encapsulation)**: 송신기에서 발생된 정보의 정확한 전송을 위해 사용자 정보의 앞뒤에 **헤더와 트레일러**를 붙이는 과정입니다. 동기화, 다중화, 주소지정은 프로토콜의 다른 기본 기능입니다.

**IP 프로토콜**: 네트워크 계층에서 실제 패킷을 전달합니다. 신뢰성, 재전송, 흐름 제어는 하지 않고, MTU보다 큰 데이터그램을 **단편화**합니다.

**Zigbee**: 저전력·저비용 근거리 무선 기술로 IEEE 802.15.4의 PHY와 MAC 계층을 기반으로 상위 프로토콜과 응용까지 규격화했고 홈 오토메이션과 유비쿼터스 센서 네트워크에 쓰입니다.

## 13. 시험 직전 점검

> - ARP: IP → MAC, RARP: MAC → IP, DHCP: 자동 할당.
> - ICMP 타입: 0 응답, 8 요청, 3 도달 불가, 5 Redirect, 11 시간 초과, 13 Timestamp, 17 Address Mask.
> - IGMP는 멀티캐스트 그룹 관리. ICMP와 IGMP는 네트워크 계층.
> - TFTP는 UDP 69, SNMP는 UDP 161, SNTP는 123, HTTPS는 443.
> - DNS TTL은 캐시 만료 시간. PTR는 역방향, SOA는 존의 첫 레코드.
> - 메일: SMTP 송신, POP3 내려받기, IMAP 서버 보관.
> - OSPF는 링크 스테이트와 Dijkstra.
> - HTTP/3은 QUIC(UDP).
