# 가상화·클라우드·임베디드

<div class="summary">

- **서버 가상화**: **KVM**은 CPU **전가상화**(x86, QEMU 사용), **Xen**은 CPU **반가상화**를 지원합니다. **Hyper-V**는 리눅스용이 아니라 마이크로소프트 기술입니다.
- **컨테이너**: **Docker**(2013년, 하이퍼바이저와 게스트 OS 없이 프로세스 격리), 배포·확장·관리 자동화는 **Kubernetes**, 구성 관리는 **Ansible**, 클라우드 구축은 **OpenStack**입니다.
- **클러스터**: **HA(고가용성)** = 주 노드와 백업 노드, **HPC(고성능·베어울프)** = 슈퍼컴퓨터와 과학계산, **부하분산** = 요청 분산입니다.
- **클라우드**: 하드웨어를 빌리면 **IaaS**, 이용자 설정이 많은 순서는 **IaaS > PaaS > SaaS**입니다.
- **임베디드·모바일 OS**: 아두이노, 라즈베리 파이, 타이젠, webOS, GENIVI. **QNX는 리눅스 커널 기반이 아닙니다.**

</div>

## 1. 서버 가상화

| 기술 | 핵심 |
|---|---|
| **KVM** | 2005년 설립된 **Qumranet**이 개발한 하이퍼바이저. 이후 **레드햇이 인수**. x86 기반 **CPU 전가상화**, **QEMU**(CPU 에뮬레이터) 사용 |
| **Xen** | **CPU 반가상화** 지원 |
| VirtualBox | 데스크톱용 가상화 소프트웨어 (리눅스에서 사용 가능) |
| Hyper-V | 마이크로소프트의 가상화 기술. **리눅스에서 사용하는 가상화 기술이 아님** |
| LXC | 리눅스 컨테이너 기술 |

| 가상 머신 파일 형식 | 제품 |
|---|---|
| **VMDK** | **VMware** |
| VDI | VirtualBox |
| VHD | 마이크로소프트(Hyper-V) |

> **함정** "CPU 반가상화"는 **Xen**, "CPU 전가상화, QEMU, Qumranet"은 **KVM**입니다. Docker는 하이퍼바이저가 아니라 컨테이너 기술이라 반가상화 보기에서 오답입니다.

## 2. 컨테이너와 자동화 도구

| 도구 | 설명 |
|---|---|
| **Docker** | 응용 프로그램과 라이브러리를 이미지로 만들어 **프로세스처럼** 동작시키는 경량 가상화. 하이퍼바이저와 게스트 OS를 쓰지 않음. **2013년** 공개 |
| **Kubernetes** | Docker 같은 컨테이너 응용의 **배포, 확장, 관리를 자동화** |
| **Ansible** | 소프트웨어 **프로비저닝, 구성 관리, 배포**. 유닉스·리눅스·윈도 지원, **2015년 레드햇이 인수** |
| **OpenStack** | 클라우드 인프라를 구축하는 오픈 소스 플랫폼 |

## 3. 클러스터

| 종류 | 목적과 특징 |
|---|---|
| **고가용성(HA, High Availability) 클러스터** | **지속적인 서비스**가 목적. **Primary Node**와 **Backup Node** 구성. 백업 노드가 주 노드의 이상 유무를 체크하다가 장애가 나면 서비스를 **이어받음** |
| **고성능(HPC) 클러스터 = 베어울프 클러스터** | 고성능 계산 능력이 목적. 주로 **과학 계산**, 흔히 말하는 **슈퍼컴퓨터** 구축 방식 |
| **부하분산 클러스터** | 로드 밸런서가 요청을 여러 서버로 분산 |

HA 클러스터 그림은 User가 Primary Node와 Backup Node에 연결되어 있고 "이상 유무 체크", "primary Node 이상 시 서비스를 이어받음" 화살표가 있는 모양입니다.

> **함정** 설명이 "주 노드와 백업 노드"이면 HA, "과학 계산·슈퍼컴퓨터"이면 HPC(베어울프)입니다. 로드 밸런서로 웹 서버를 운영하는 상황을 묻는 문제에서 보기에 부하분산 클러스터가 없으면 서비스를 계속 제공하는 구성인 고가용성 클러스터가 정답으로 출제된 적이 있습니다(2023년 12월).

## 4. 클라우드 서비스 유형

| 유형 | 제공 | 설명 |
|---|---|---|
| **IaaS** | 인프라 | 서버, 데스크톱, 스토리지 같은 **IT 하드웨어 자원을 빌려** 사용 |
| PaaS | 플랫폼 | 개발·실행 환경을 빌려 사용 |
| SaaS | 소프트웨어 | 완성된 응용 프로그램을 사용 |
| DaaS | 데스크톱 | 가상 데스크톱을 서비스로 사용 |

이용자가 설정할 수 있는 범위는 **IaaS > PaaS > SaaS** 순입니다. 아래로 갈수록 업체가 맡는 범위가 넓어집니다.

## 6. 임베디드·모바일·기타 운영체제

| 이름 | 설명 |
|---|---|
| **아두이노(Arduino)** | 오픈 소스 기반 **단일 보드 마이크로컨트롤러**. **2005년 이탈리아** IDII에서 개발. 마이크로컨트롤러를 내장해 특정 기능을 반복 수행하는 전자 제어 시스템과 관련 |
| **라즈베리 파이** | **영국** 재단이 학교와 개발도상국의 기초 컴퓨터 과학 교육을 위해 개발한 **신용카드 크기의 싱글 보드 컴퓨터** |
| 마이크로비트, 큐비보드, 오드로이드 | 다른 싱글 보드 제품 |
| **타이젠(Tizen)** | **인텔과 삼성**이 주축, 리눅스 재단과 MeeGo 개발자가 합류. 리눅스 커널 기반 모바일 OS |
| **webOS** | 리눅스 커널 기반 모바일 OS, **Palm OS를 계승**, 현재 **LG전자**가 주도 |
| **GENIVI** | **2009년 2월** BMW, 델파이, GM, 인텔, 윈드리버 등이 설립. 리눅스 커널 기반 자동차용 **IVI**(In-Vehicle Infotainment) 플랫폼 |
| QNX | **리눅스 커널 기반이 아님** |
| Bada OS | 삼성의 모바일 OS (보기 중 인텔·삼성·리눅스 재단 설명에는 해당하지 않음) |

> **함정** "리눅스 커널 기반이 **아닌**" 운영체제를 고르는 문제에서는 **QNX**가 정답입니다. webOS, Tizen, GENIVI는 모두 리눅스 커널 기반입니다.

## 8. 시험 직전 점검

> - 반가상화는 Xen, 전가상화는 KVM(QEMU, Qumranet).
> - Hyper-V는 리눅스용 가상화가 아님. VMware 파일은 VMDK.
> - Docker는 2013년, Kubernetes는 컨테이너 자동화, Ansible은 2015년 레드햇 인수.
> - 주 노드와 백업 노드는 HA 클러스터, 슈퍼컴퓨터는 HPC(베어울프).
> - 이용자 설정이 많은 순서: IaaS, PaaS, SaaS.
> - 리눅스 기반이 아닌 OS는 QNX.
> - Rocky Linux는 CentOS 창립자가 주도.

## 9. OX 점검

| 문장 | 답 | 이유 |
|---|---|---|
| KVM은 CPU 반가상화를 지원한다. | X | 전가상화입니다. 반가상화는 Xen입니다. |
| Hyper-V는 리눅스용 가상화 기술이다. | X | 마이크로소프트 기술입니다. |
| Docker는 하이퍼바이저와 게스트 OS를 사용하지 않는다. | O | |
| Kubernetes는 컨테이너 응용의 배포·확장·관리를 자동화한다. | O | |
| HA 클러스터는 슈퍼컴퓨터를 만드는 방식이다. | X | HPC(베어울프) 클러스터입니다. |
| IaaS는 SaaS보다 이용자의 설정 범위가 넓다. | O | |
| QNX는 리눅스 커널 기반 운영체제이다. | X | 아닙니다. |
| 라즈베리 파이는 이탈리아에서 개발되었다. | X | 영국입니다. 이탈리아에서 개발된 것은 아두이노입니다. |
