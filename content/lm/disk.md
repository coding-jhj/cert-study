# 디스크·파일 시스템·쿼터·LVM·RAID

<div class="summary">

- **파티션 → 파일 시스템 → 마운트** 순서로 디스크를 씁니다. 파티션은 `fdisk`, 파일 시스템 생성은 `mkfs`(XFS는 `mkfs.xfs`, ext4는 `mke2fs -t ext4`), 연결은 `mount`입니다.
- **부팅 때 자동 마운트**는 `/etc/fstab`(6칸, 4번째가 옵션), **지금 마운트된 목록**은 `/etc/mtab`입니다.
- **점검·복구**는 ext 계열이 `fsck`·`e2fsck`, XFS가 `xfs_repair`입니다.
- **용량**은 `df`(파티션 단위 남은 용량), `du`(파일·디렉터리가 차지하는 용량)로 확인합니다.
- **쿼터**는 확인 `quota`, 설정 `edquota`, 전체 보고 `repquota`, XFS 전용 `xfs_quota`입니다.
- **LVM**은 PV → VG → LV 순서로 만들고, **RAID**는 0(성능)·1(복제)·5(패리티)·6(이중 패리티)을 용량 계산과 함께 외웁니다.

</div>

## 1. 파티션과 장치 이름

하드디스크는 `/dev/sda`, `/dev/sdb`처럼 이름 붙고, 그 안의 파티션은 `/dev/sda1`, `/dev/sda2`처럼 번호가 붙습니다.

| 확인 명령 | 보여 주는 것 |
|---|---|
| `fdisk -l` | 장착된 디스크들의 **파티션 테이블** 정보 |
| `lsblk` | 디스크와 파티션을 나무 모양으로(NAME, SIZE, TYPE, MOUNTPOINT) |
| `blkid` | 파티션의 **UUID**와 파일 시스템 종류(TYPE) |

`fdisk /dev/sdb`로 들어간 뒤 쓰는 키입니다.

| 키 | 동작 |
|---|---|
| `n` | 새 파티션 |
| `d` | 파티션 삭제 |
| `p` | 파티션 목록 출력 |
| `t` | 파티션 종류(ID) 변경 |
| `w` | **저장하고 종료** |
| `q` | **저장하지 않고 종료** |

`/dev/sda3`이 `1K`로 보이는 파티션은 보통 확장 파티션입니다. 논리 파티션은 5번부터 시작합니다(`sda5`, `sda6`).

## 2. 파일 시스템 만들기와 종류

| 종류 | 설명 | 만드는 명령 |
|---|---|---|
| ext2, ext3, ext4 | 리눅스의 전통 파일 시스템(ext3부터 저널링) | `mke2fs -t ext4 장치`, `mkfs.ext4` |
| XFS | **CentOS 7의 기본**, 대용량·고성능 | `mkfs.xfs 장치` |
| swap | 메모리 부족 때 쓰는 교환 영역 | `mkswap` |
| NTFS | 윈도 파일 시스템 | |
| CIFS(SMB) | 윈도 공유 폴더를 네트워크로 마운트 | `mount -t cifs` |

> **함정** XFS는 `mkfs.xfs`입니다. `xfs_mkfs`나 `xfs.mkfs`는 없는 명령입니다. 이름 앞뒤 순서와 점(`.`)·밑줄(`_`)에 주의합니다.

## 3. 마운트

```
# mount -t xfs /dev/sdb1 /backup         # 장치 먼저, 마운트 지점 나중
# mount -o remount,rw /home              # 옵션만 바꿔 다시 마운트
# umount /backup                         # n이 없는 umount
# eject /dev/cdrom                       # CD-ROM 트레이 열기
# mount -t cifs //192.168.5.13/data /mnt -o username=administrator,password=1234
```

- 장치 → 마운트 지점 순서입니다. `-t 종류`, `-o 옵션`입니다.
- 마운트 해제는 `umount`입니다(`unmount`는 없습니다).
- 인자 없는 `mount`는 마운트된 파일 시스템 목록을 보여 줍니다(`/dev/sda1 on / type xfs (rw,...)` 형식).

### /etc/fstab — 부팅 때 자동 마운트

6개의 칸이 공백으로 나뉘어 있습니다.

| 칸 | 내용 | 예 |
|---|---|---|
| 1 | 장치 (장치 파일명, `UUID=`, `LABEL=`) | `UUID=7e14...` |
| 2 | 마운트 지점 | `/` |
| 3 | 파일 시스템 종류 | `xfs` |
| 4 | **마운트 옵션** | `defaults`, `noexec`, `usrquota` |
| 5 | dump 여부 | `0` |
| 6 | 부팅 때 fsck 순서 | `0` |

`/etc/mtab`은 **현재 마운트된 파일 시스템 정보**를 담습니다(실제 원본은 `/proc/self/mounts`). 부팅 때 자동으로 마운트할 목록을 적는 파일은 `fstab`입니다.

## 4. 점검과 복구

| 파일 시스템 | 명령 |
|---|---|
| ext2, ext3, ext4 | `fsck`, `e2fsck` |
| XFS | `xfs_repair 장치` |

`xfs.fsck`라는 명령은 없습니다. 파일 시스템 종류에 따라 명령이 다르다는 점이 시험 포인트입니다.

## 5. 용량 확인

| 명령 | 의미 | 예 |
|---|---|---|
| `df` | 마운트된 **파티션 단위**의 전체·사용·남은 용량 | `df -hT` (사람이 읽기 쉬운 단위, 종류 표시) |
| `du` | 파일·디렉터리가 **차지하는 용량** | `du -sh ~ihduser` (`-s` 합계, `-h` 읽기 쉬운 단위) |
| `free` | **메모리** 사용량 | |

"남은 용량"은 `df`, "특정 사용자나 디렉터리가 쓰는 양"은 `du`입니다. `df`의 출력에는 `Filesystem / Size / Used / Avail / Use% / Mounted on` 열이 있고, `-T`를 주면 `Type`이 추가됩니다.

용량 단위는 `KB < MB < GB < TB < PB < EB` 순서입니다.

## 6. 디스크 쿼터

사용자나 그룹이 쓸 수 있는 **디스크 용량·파일 수를 제한**하는 기능입니다. `/etc/fstab`의 옵션 칸에 `usrquota`(사용자), `grpquota`(그룹)를 적고 다시 마운트해서 켭니다. XFS에서는 `uquota`, `gquota`도 쓰고, 단순히 `quota`만 써도 됩니다. `userquota`는 없는 값입니다.

| 명령 | 역할 |
|---|---|
| `quota 사용자` | 사용자의 쿼터 **설정 정보 확인** |
| `edquota 사용자` | 쿼터를 **설정**(vi 편집기가 열려 값을 입력) |
| `setquota` | 명령행에서 값을 직접 주어 설정 |
| `repquota 마운트지점` | 파일 시스템 전체의 **사용자별 쿼터 보고서** |
| `xfs_quota` | **XFS 전용** 쿼터 명령. CentOS 7에서 쓰는 쿼터 제한 명령 |

```
# xfs_quota -x -c 'limit bsoft=100m bhard=100m ihduser' /home
```

보고서의 `soft`(경고 한도), `hard`(절대 한도), `grace`(soft를 넘은 뒤 허용되는 유예 기간, 기본 7일) 열을 읽을 수 있어야 합니다. `Report for user quotas` 제목과 `User used soft hard grace` 열 머리가 보이면 `repquota`입니다.

## 7. LVM

LVM은 여러 디스크를 하나로 묶어 크기를 유연하게 쓰는 기술입니다. **만드는 순서는 PV → VG → LV**입니다.

| 용어 | 뜻 |
|---|---|
| PV (Physical Volume) | 물리적 볼륨. 디스크나 파티션을 LVM이 쓸 수 있게 한 것 |
| VG (Volume Group) | PV를 묶은 큰 저장 풀 |
| LV (Logical Volume) | VG에서 필요한 만큼 떼어 만든 **파티션과 같은 개념**의 공간. 여기에 파일 시스템을 만듭니다. |
| PE (Physical Extent) | VG를 이루는 **기본 단위 블록**. 보통 **4MB** |

- 디스크 2개를 하나의 파티션처럼, 디스크 1개를 여러 파티션으로 쓸 수 있습니다.
- **확장은 데이터 손실 없이 가능**합니다. **축소는 손실 위험이 있어 주의**가 필요합니다. "축소해도 손실이 없다"는 틀린 설명입니다.
- "500GB 디스크 2개로 700GB·200GB·100GB 파티션을 만들어야 한다"처럼 디스크 경계를 넘는 유연한 구성이 필요하면 **LVM**입니다.

## 8. RAID

| 방식 | 구성 | 최소 디스크 | 가용 용량 | 디스크 고장 |
|---|---|---|---|---|
| RAID-0 (Striping) | 데이터를 나눠 번갈아 기록(라운드 로빈), **가장 빠름** | 2 | 전부(100%) | **1개만 고장나도 복구 불가** |
| RAID-1 (Mirroring) | 같은 데이터를 복제 | 2 | 50% | 1개 고장 허용 |
| RAID-5 | 패리티를 분산 저장 | 3 | (n-1)개 분량 | 1개 고장 허용 |
| RAID-6 | 패리티 2개 | 4 | (n-2)개 분량 | 2개 고장 허용 |

용량 계산 예입니다.

- 2GB 디스크 7개 RAID-6: (7-2)×2 = **10GB**
- 10GB 디스크 4개 RAID-0: 4×10 = **40GB**
- 10GB 디스크 8개, 스페어 1개 + RAID-5: 쓰는 디스크 7개이므로 (7-1)×10 = **60GB**
- 디스크 4개에서 용량 효율 50%인 조합: RAID-1과 RAID-6
- 디스크 3개 RAID-5: 패리티가 차지하는 비율 약 **33.3%**

스페어(Spare) 디스크는 평소에는 대기하다가 고장난 디스크를 자동으로 대체합니다. 용량 계산에 포함하지 않습니다.

## 9. 시험 직전 점검

> - "부팅 때 자동 마운트"는 `fstab`, "현재 마운트 정보"는 `mtab`입니다.
> - `df`는 파티션의 **남은 용량**, `du`는 디렉터리의 **사용량**입니다.
> - XFS는 `mkfs.xfs`, `xfs_repair`, `xfs_quota`입니다.
> - 쿼터 설정은 `edquota`, 확인은 `quota`, 전체 보고는 `repquota`입니다.
> - LVM은 PV → VG → LV, PE는 4MB입니다.
> - RAID-0은 한 개만 고장나도 복구가 안 됩니다.

## 10. OX 점검

| 문장 | 답 | 이유 |
|---|---|---|
| `fdisk`에서 `q`를 누르면 변경 내용을 저장하고 종료한다. | X | `q`는 저장하지 않고 종료합니다. 저장은 `w`입니다. |
| `unmount /backup`으로 마운트를 해제한다. | X | `umount`입니다. |
| `/etc/fstab`의 4번째 칸은 마운트 옵션이다. | O | |
| `df`는 파일이나 디렉터리가 차지하는 용량을 보여 준다. | X | 파티션 단위 남은 용량입니다. 사용량은 `du`입니다. |
| `repquota`는 사용자별 쿼터 보고서를 출력한다. | O | |
| LVM에서 LV를 축소해도 데이터 손실이 없다. | X | 축소는 손실 위험이 있습니다. |
| RAID-1은 디스크 2개 중 1개가 고장나도 데이터를 쓸 수 있다. | O | 같은 데이터를 복제해 두기 때문입니다. |
| 10GB 디스크 4개를 RAID-0으로 묶으면 쓸 수 있는 용량은 20GB이다. | X | RAID-0은 전부 쓰므로 40GB입니다. |
