# IPv6

<div class="summary">

- **IPv6 주소**는 **128비트**, 16진수 4자리씩 8묶음을 `:`로 구분합니다(예: `3ffe:1900:4545:0003:0200:f8ff:ffff:1105`).
- **IPv4 주소 부족**을 해결하려고 **IETF**가 만들었습니다. 헤더는 단순해졌고 **인증·보안**이 강화되었으며 **자동 설정(Autoconfiguration)**이 새로 들어왔습니다.
- **클래스 구분이 없고, 브로드캐스트도 없습니다.** 주소 유형은 유니캐스트, 멀티캐스트, 애니캐스트입니다.
- **생략 규칙**: 묶음 앞의 0은 생략, 연속된 0 묶음은 `::` (주소에 **한 번만**).
- **전환 기술**은 듀얼 스택, 터널링, 프로토콜 변환입니다.

</div>

## 1. IPv6의 특징

| 항목 | IPv4 | IPv6 |
|---|---|---|
| 주소 길이 | 32비트 | **128비트** |
| 클래스 | A-E 클래스 | **클래스 구분 없음** |
| 헤더 | 복잡 | **단순화** |
| 보안 | 선택 | **인증 및 보안 기능 강화** (IPsec 사용 가능) |
| 주소 설정 | 수동/DHCP | **자동 설정(Autoconfiguration, SLAAC)** |
| 전송 방식 | 유니캐스트, 브로드캐스트, 멀티캐스트 | 유니캐스트, **멀티캐스트**, 애니캐스트 (**브로드캐스트 없음**) |
| 모바일 | | 모바일 IP, IPsec 프로토콜 사용 가능 |

IETF(Internet Engineering Task Force)가 IPv4의 주소 부족 문제를 해결하려고 만들었습니다.

> **함정** "4개의 클래스로 구분된다", "브로드캐스트를 사용한다", "복잡한 헤더"는 IPv6의 특징이 아닙니다. IPv6에서 **새롭게** 제공되는 기능으로 묻는 문제의 답은 **Autoconfiguration**입니다. Checksums, Complicated header, Optional IPsec은 IPv4 쪽의 모습입니다. 옵션 설정이 더 다양한 쪽도 IPv4가 아니라 IPv6입니다.

## 2. 헤더 필드

| 필드 | 역할 |
|---|---|
| Version | IP 버전 |
| **Priority** (Traffic Class) | 네트워크가 **혼잡**할 때 어떤 데이터그램을 버릴지 **참조**하는 우선순위 |
| Next Header | 다음 헤더 종류 |
| **Hop Limit** | 데이터그램의 **생존 기간**(IPv4의 TTL에 해당) |

### 확장 헤더

| 확장 헤더 | 용도 |
|---|---|
| **Fragmentation** | 6000바이트 패킷이 이더넷 LAN(MTU 1500)을 지나야 할 때 **분할**에 사용 |
| Source Routing | 경로 지정 |
| Authentication | 인증 |
| Destination Option | 목적지 옵션 |

## 3. 주소 표기와 생략

규칙은 두 가지입니다.

1. 각 16비트 묶음의 **앞쪽 0은 생략**할 수 있습니다. 묶음이 모두 0이면 `0`으로 씁니다.
2. 연속된 0 묶음은 **`::`** 로 줄입니다. 주소 하나에 **한 번만** 쓰고, 길이가 같은 0 구간이 여럿이면 **가장 왼쪽**을 줄입니다. 0 묶음이 **하나뿐이면** `::`로 줄이지 않고 `0`으로 씁니다(RFC 5952).

`::`는 모자란 묶음 수를 0으로 채웁니다. 복원할 때는 전체가 8묶음이 되도록 `::` 자리에 `0000`을 넣습니다.

| 원래 주소 | 생략 표기 |
|---|---|
| `a184:0a01:0000:0000:cd8c:1000:317b:00ff` | **`a184:a01::cd8c:1000:317b:ff`** |
| `2000:00AB:0001:0000:0000:0000:0001:0002` | `2000:AB:1::1:2` |

> **함정** 선행 0만 지우고 뒤쪽 0은 지우지 않습니다. `1000`을 `1`로 줄이면 안 되고 `0a01`은 `a01`로 줄입니다. 복원 문제는 `::`가 몇 묶음을 대신하는지 세어서, 전체가 8묶음이 되는 보기를 고릅니다.

> **함정** IPv6 표기가 맞는지는 묶음 수와 구분자로 봅니다. `192.168.1.30`은 IPv4, `00:A0:C3:4B:21:33`은 MAC 주소(6묶음), `0000:002A:0080:c703:3c75`는 5묶음만 있어 `::` 없이는 올바른 표기가 아닙니다.

## 4. IPv4에서 IPv6로의 전환 기술

| 기술 | 내용 |
|---|---|
| **듀얼 스택(Dual Stack)** | 한 장치가 IPv4와 IPv6를 동시에 지원 |
| **터널링(Tunneling)** | IPv6 패킷을 IPv4 망 위로 캡슐화해 전달 |
| **프로토콜 변환(Protocol Translation)** | IPv4와 IPv6 사이를 변환 |
| 네트워크 주소 변환(NAT44) | IPv4 사설-공인 변환일 뿐 전환 기술이 아님 |

## 5. 시험 직전 점검

> - 128비트, 클래스 없음, 브로드캐스트 없음, 헤더 단순, 보안 강화, 자동 설정.
> - 혼잡 시 버릴 데이터그램은 Priority, 생존 기간은 Hop Limit.
> - 큰 패킷 분할은 Fragmentation 확장 헤더.
> - `::`는 한 번만, 앞쪽 0만 생략, 0 묶음이 하나면 `0`.
> - 전환 기술: 듀얼 스택, 터널링, 프로토콜 변환.
