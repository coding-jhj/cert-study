# 프로세스와 cron

<div class="summary">

- **프로세스**는 실행 중인 프로그램입니다. CentOS 7의 최초 프로세스는 **systemd(PID 1)**이고, CentOS 6까지는 init였습니다.
- 새 프로세스를 만드는 방식은 **fork**(복사본을 만들어 자식 프로세스 생성)와 **exec**(현재 프로세스를 새 프로그램으로 **교체**, 프로세스 수가 늘지 않음)입니다.
- 데몬 실행 방식은 **standalone**(계속 상주, 응답이 빠름)과 **inetd**(요청이 올 때만 실행, 메모리 효율이 좋음)입니다.
- 시그널 번호는 **1 HUP, 2 INT, 9 KILL, 15 TERM, 20 TSTP**입니다. `kill`의 기본은 15입니다.
- 우선순위(NI)는 **-20부터 19까지**이고 `nice`·`renice`로 바꿉니다.
- cron은 **분 시 일 월 요일** 다섯 칸입니다.

</div>

## 1. 프로세스 기본

| 용어 | 뜻 |
|---|---|
| PID | 프로세스 번호 |
| PPID | 부모 프로세스의 PID |
| NI | 사용자가 정하는 우선순위 값(nice). **작을수록 우선순위가 높음** |
| PRI | 커널이 사용하는 우선순위 값 |
| daemon | 서비스 요청을 처리하려고 메모리에 계속 실행되어 있는 **백그라운드 프로세스** |

`ps`의 STAT 열에서 자주 나오는 상태 코드입니다.

| 코드 | 상태 |
|---|---|
| `R` | 실행 중 |
| `S` | 잠자는 중(대기) |
| `T` | 중지됨 |
| `Z` | **좀비**. 작업은 끝났지만 부모가 회수하지 않아 메모리를 차지하는 상태 |

CentOS 7은 부팅하면 커널이 **systemd**를 PID **1**로 만들고, 이후의 모든 프로세스는 systemd의 자식입니다. 새 프로세스는 부모의 **fork**로 만들어지고, 그래서 자식의 PPID는 부모의 PID입니다.

## 2. fork와 exec

| | fork | exec |
|---|---|---|
| 동작 | 부모의 **복사본**을 새로 만듦 | 현재 프로세스의 메모리를 새 프로그램으로 **덮어씀** |
| 프로세스 수 | **늘어남**(부모는 계속 실행) | **늘지 않음**(교체) |
| 예 | 로그인 후 명령을 입력하면 bash의 자식으로 명령이 실행됨 | `exec ps -l`처럼 셸이 ps로 바뀜 |

셸에서 명령을 실행하면 `fork`로 자식을 만들고 그 자식이 `exec`로 해당 프로그램이 됩니다. `pstree`의 나무 모양은 fork의 결과입니다.

## 3. 데몬 — standalone과 inetd

| | standalone | inetd(xinetd) |
|---|---|---|
| 방식 | 부팅 때 실행되어 메모리에 **계속 상주** | 요청이 올 때 **실행**, 끝나면 종료 |
| 장점 | 응답이 빠름 | **메모리 관리가 효율적** |
| 적합한 서비스 | 웹·메일처럼 **요청이 잦은** 서비스 | rlogin, rsh처럼 **잘 쓰이지 않는** 서비스 |

inetd는 여러 서비스의 포트를 대신 **리슨(listen)**하다가 요청이 오면 해당 서버 프로그램을 실행하는 "슈퍼 데몬"입니다. standalone은 "단독 데몬 방식"이라고도 합니다.

## 4. 프로세스 확인

| 명령 | 하는 일 |
|---|---|
| `ps aux`, `ps -ef` | **모든** 프로세스 목록 (옵션 `a`, `u`, `x`는 앞에 `-`가 없는 BSD 형식) |
| `ps -l` | 긴 형식. **NI, PRI** 확인 |
| `pstree` | 프로세스의 부모·자식 관계를 **나무 모양**으로 |
| `top` | **실시간**으로 CPU·메모리 사용률과 프로세스를 갱신해서 보여 줌 |
| `jobs` | 현재 셸의 **백그라운드·중지 작업** 목록(작업 번호) |
| `pgrep 이름` | 이름으로 PID 검색 |

출력을 보고 명령을 맞히는 문제가 자주 나옵니다.

- `USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND` 열에 `[kthreadd]` 같은 항목 → `ps`
- `systemd-+-ModemManager---...` 나무 → `pstree`
- 맨 위에 `top - 10:41:40 up ... load average`, `Tasks:`, `%Cpu(s):`, `KiB Mem` 줄 → `top`

## 5. 포그라운드와 백그라운드

| 조작 | 동작 |
|---|---|
| 명령 **뒤**에 `&` | 처음부터 백그라운드로 실행 (`find / -name '*.txt' > list &`) |
| `Ctrl+Z` | 포그라운드 작업을 **일시 중지(suspend)**(시그널 TSTP) |
| `bg` | 중지된 작업을 백그라운드에서 **다시 실행** |
| `fg` | 백그라운드 작업을 포그라운드로 |
| `Ctrl+C` | 포그라운드 작업 **종료**(시그널 INT) |
| `jobs` | 작업 목록과 번호 |
| `kill %2` | **작업 번호 2번** 종료 (`%`가 작업 번호 표시) |
| `nohup 명령 &` | **터미널이 닫혀도** 계속 실행 |

> **함정** `Ctrl+Z`는 중지입니다. 백그라운드로 보내 계속 실행하려면 이어서 `bg`를 입력합니다. `bg 명령`이나 `jobs 명령`처럼 명령 앞에 붙이는 형식은 없습니다.

## 6. 시그널

| 번호 | 이름 | 의미·발생 |
|---|---|---|
| 1 | SIGHUP | 터미널 연결 끊김, 설정 다시 읽기 |
| 2 | SIGINT | `Ctrl+C` |
| 3 | SIGQUIT | `Ctrl+\` |
| 9 | SIGKILL | **강제 종료**(무시할 수 없음) |
| 15 | SIGTERM | **정상 종료 요청**. `kill`의 **기본값** |
| 19 | SIGSTOP | 중지 (`Ctrl+Z`가 아님) |
| 20 | SIGTSTP | `Ctrl+Z` |

`kill -l`로 시그널의 이름과 번호 목록을 확인합니다.

## 7. 프로세스 종료

```
# kill 513               # 15번(SIGTERM)
# kill -9 1222           # 강제 종료
# kill 513 514 515       # 여러 PID 한 번에
# kill %2                # 작업 번호 2
# killall vsftpd         # 이름으로 모두 종료
```

- `kill`은 **PID**(또는 `%작업번호`)를 받고, `killall`과 `pkill`은 **프로세스 이름**을 받습니다.
- 사용자를 강제로 로그아웃시키는 것처럼 기본 종료 시그널로 안 끝나는 프로세스는 **9번**으로 끝냅니다.

## 8. 우선순위 — nice와 renice

NI는 **-20(우선순위 가장 높음)부터 19(가장 낮음)**입니다. 일반 사용자는 값을 **올리기**(우선순위 낮추기)만 할 수 있고 낮추는 것은 root만 가능합니다.

| 명령 | 의미 |
|---|---|
| `nice -10 bash` | 기존 값에 **+10**을 더해 실행(NI 10, 우선순위 낮아짐) |
| `nice --10 bash` | **-10**을 적용해 실행(우선순위 높아짐, root만). 옵션 형태는 `-n 숫자`와 같음 |
| `nice bash` | 값을 안 주면 **+10**(우선순위 낮아짐) |
| `renice 10 1222` | **이미 실행 중인 PID 1222**의 NI를 10으로 변경 |
| `renice -10 1222` | PID 1222의 NI를 -10으로 변경 |

- `nice`는 **새로 실행할 때** 값을 정하고, `renice`는 **실행 중인 프로세스(PID)**의 값을 바꿉니다.
- `renice -10 bash`처럼 PID 자리에 이름을 쓰면 사용법 오류입니다.

## 9. cron — 주기적 실행

`crontab -e`로 편집하고 한 줄에 **분 시 일 월 요일 명령**을 씁니다.

| 칸 | 범위 |
|---|---|
| 분 | 0-59 |
| 시 | 0-23 |
| 일 | 1-31 |
| 월 | 1-12 |
| 요일 | 0-7 (0과 7이 일요일, 1 월요일 … 6 토요일) |

| 하려는 일 | cron 표기 |
|---|---|
| 5분마다 | `*/5 * * * *` |
| 10분마다 | `0-59/10 * * * *` 또는 `*/10 * * * *` |
| 월요일부터 금요일까지 12시 정각 | `0 12 * * 1-5` |
| 매주 월요일 10시 2분 | `2 10 * * 1` |
| 매주 월요일과 수요일 11시 10분 | `10 11 * * 1,3` |
| 토요일과 일요일 4시 1분 | `1 4 * * 0,6` |
| 매월 1일 4시 2분 | `2 4 1 * *` |
| 매주 1회(요일만 지정) | `1 1 * * 1` |

**맨 앞이 분, 두 번째가 시**입니다. "오전 4시 2분"은 `2 4 ...`로 분이 앞입니다. 요일은 다섯 번째 칸, 일은 세 번째 칸이어서 "매주"는 요일 칸에, "매월 1일"은 일 칸에 숫자를 씁니다.

| 명령 | 의미 |
|---|---|
| `crontab -e` | 내 crontab 편집 |
| `crontab -l` | 목록 확인 |
| `crontab -r` | 삭제 |
| `crontab -u 사용자` | 다른 사용자의 crontab 지정 |

## 10. 시험 직전 점검

> - 시그널 번호: HUP 1, INT 2, KILL 9, TERM 15, TSTP 20. `kill` 기본은 15입니다.
> - `Ctrl+Z`는 "중지", 백그라운드로 보내 이어 실행하려면 `bg`입니다.
> - 새 프로세스: fork는 복사(늘어남), exec는 교체(안 늘어남).
> - 요청이 잦은 서비스는 standalone, 가끔 쓰는 서비스는 inetd입니다.
> - cron은 분이 맨 앞입니다. `0 12 * * 1-5`는 평일 정오입니다.

## 11. OX 점검

| 문장 | 답 | 이유 |
|---|---|---|
| CentOS 7의 최초 프로세스는 init이다. | X | systemd입니다(PID 1). |
| exec는 프로세스 수를 늘린다. | X | 현재 프로세스를 교체합니다. |
| 요청이 빈번한 웹 서비스는 inetd 방식이 적합하다. | X | standalone이 적합합니다. |
| `kill 513`은 513번 프로세스에 SIGTERM(15)을 보낸다. | O | 기본 시그널이 15입니다. |
| `Ctrl+Z`는 포그라운드 작업을 종료한다. | X | 일시 중지합니다. 종료는 `Ctrl+C`입니다. |
| `nice`로 정할 수 있는 NI 값의 범위는 -20부터 19까지이다. | O | |
| `renice -10 bash`는 bash의 우선순위를 높인다. | X | `renice`는 PID를 받으므로 사용법 오류입니다. |
| `5 4 * * *`는 매일 4시 5분에 실행한다. | O | 분 시 순서입니다. |
