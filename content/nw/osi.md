# OSI 참조 모델과 데이터 전송

<div class="summary">

- **OSI 7계층**(하위부터): 물리 → 데이터링크 → 네트워크 → 전송 → 세션 → 표현 → 응용. 데이터 단위는 **비트 → 프레임 → 패킷 → 세그먼트 → 데이터**입니다.
- **데이터링크**: 프레임화, 오류 검출, 흐름 제어, 링크 관리. **표현**: 암호/복호, 압축, 형식 변환. **세션**: 대화 제어, 연결 설정·종료, 동기화. **전송**: 흐름 제어와 오류 없는 전송.
- **프로토콜의 3요소**는 구문(Syntax), 의미(Semantics), **타이밍(Timing)** 입니다.
- **ARQ**: Stop-and-Wait, **Go-back-N**(오류 난 블록부터 모두 재전송), **Selective**(오류 난 것만), **Adaptive**(프레임 길이 동적 변경).
- **다중화**: TDM(빈 슬롯도 할당, 낭비), STDM(통계적), FDM, WDM(광).

</div>

## 1. 계층별 역할과 단위

| 계층 | 번호 | 역할 | 데이터 단위 |
|---|---|---|---|
| 응용 | 7 | 응용 프로그램 인터페이스와 응용 기능 | 데이터 |
| 표현 | 6 | **암호/복호, 인증, 압축**, 서로 다른 형식을 **표준 형식으로 변환** | 데이터 |
| 세션 | 5 | **대화 제어**, **연결 설정·종료**, **동기화**, 프로세스 간 통신 | 데이터 |
| 전송 | 4 | **흐름 제어, 오류 없는 전송**, 양단 간 메시지가 올바른 순서로 도착 | **세그먼트** |
| 네트워크 | 3 | 경로 선택, 주소 지정 | **패킷** |
| 데이터링크 | 2 | 비트열을 **프레임화**, **전송 오류 검출·제어**, **흐름 제어**, **링크 관리**. 프로토콜 예: SLIP, PPP | **프레임** |
| 물리 | 1 | 비트 전송 | **비트** |

> **함정** 에러 제어는 데이터링크(와 전송) 계층의 기능이고 **세션 계층의 역할이 아닙니다**. "Text의 압축, 암호 기능"은 데이터링크 계층이 아니라 **표현 계층**입니다. 데이터링크는 OSI 7계층 중 **두 번째** 계층이고 세 번째가 아닙니다. "응용 프로그램 인터페이스와 응용 기능"은 응용 계층이며 데이터링크가 아닙니다.

**TCP/IP와 OSI 대응**

| 프로토콜 | OSI 계층 |
|---|---|
| TCP, UDP | 전송 |
| IP, ICMP, RARP | 네트워크 |
| FTP, HTTP, TFTP, NNTP | **응용** (HTTP는 표현 계층이 아님) |
| PPP, SLIP | 데이터링크 |

"TCP/IP 계층 중 다른 계층에서 동작하는 것"을 고르면 IP, ICMP, RARP는 네트워크 계층이고 **NNTP**만 응용 계층입니다.

## 2. 캡슐화

| 방향 | 용어 | 내용 |
|---|---|---|
| 송신: 상위 → 하위 | **캡슐화** | 계층을 지날 때마다 **헤더**가 추가됨 |
| 수신: 하위 → 상위 | **역캡슐화** | 헤더를 읽어 처리하고 **제거**함 |

## 3. 프로토콜의 구성과 기능

| 구성 요소 | 의미 |
|---|---|
| 구문(Syntax) | 데이터 형식, 부호화 |
| 의미(Semantics) | 제어 정보, 오류 처리 |
| **타이밍(Timing)** | **통신 속도와 메시지 순서** 제어 정보 |

| 프로토콜 기능 | 설명 |
|---|---|
| **흐름 제어(Flow Control)** | 수신 측이 송신 측에서 오는 **데이터의 양이나 속도를 제한** |
| **오류 제어(Error Control)** | 보낸 PDU의 ACK를 일정 시간 받지 못하면 **재전송** |
| 순서 제어(Sequence Control) | 데이터 순서 유지 |
| 접속(연결) 제어 | 연결 설정과 해제 |

**흐름 제어 방식**: Stop and Wait, XON/XOFF, Sliding Window. **Loop/Echo**는 흐름 제어와 관계가 없습니다.

## 4. ARQ와 오류 제어

| ARQ | 동작 |
|---|---|
| **Stop-and-Wait** | 한 블록 보내고 ACK를 기다림 |
| **Go-back-N** | 에러가 난 블록으로 **되돌아가 그 뒤의 모든 블록을 재전송** |
| **Selective Repeat** | **에러가 난 블록만** 재전송 |
| **Adaptive** | 전송 효율을 높이려고 **프레임 길이를 동적으로 변경** |

> **함정** FEC(Forward Error Correction)는 수신 측이 스스로 오류를 정정하므로 **재전송을 요청하는 자동 재전송 기법이 아닙니다**. 채널 부호화는 에러 검출·정정용 비트를 추가하는 기술이고, **Convolutional Code**가 해당합니다. ADPCM, ADM, PCM은 아날로그 신호를 디지털로 바꾸는 **원천 부호화** 방식입니다.

## 5. LAN의 매체 접근: CSMA/CD

버스 구조에서 전송 전에 **채널이 사용 중인지 검사**하고, 비어 있으면 어느 노드든 사용할 수 있으며, 동시에 전송하면 **충돌**이 일어나 데이터를 폐기하고 일정 시간 **대기 후 재전송**합니다. Token Ring, Token Bus, Slotted Ring은 토큰이나 슬롯으로 차례를 정하는 방식입니다.

## 6. 다중화

| 방식 | 특징 |
|---|---|
| **Multiplexing** | 여러 터미널이 **하나의 통신 회선**으로 신호를 보내고 수신 측에서 다시 분리 |
| **TDM** | 전송할 데이터가 없어도 **타임 슬롯을 할당**해 **대역폭이 낭비**됨 |
| **STDM** | 데이터가 있는 터미널에만 슬롯을 할당(통계적) |
| FDM | 주파수 분할 |
| **WDM** | 광증폭기로 **무중계 장거리 전송**이 가능, 파장(주파수) 축 다중화, 선로 증설 없이 **회선 증설이 쉬움**, 채널마다 전송 형식·속도·프로토콜이 달라도 됨 |

> **함정** WDM은 시간축이 아니라 **파장(주파수)축** 다중화입니다. 선로를 늘리지 않고도 회선을 늘릴 수 있는 것이 장점입니다.

## 7. 전송 손실

| 현상 | 의미 |
|---|---|
| 감쇠(Attenuation) | 거리에 따라 신호 크기가 줄어듦 |
| **위상 왜곡(Phase Distortion)** | 여러 주파수 성분이 **서로 다른 지연시간**으로 도달 |
| 누화(Crosstalk) | 인접 선로 신호 간섭 |
| 충격성 잡음(Impulse Noise) | 순간적으로 큰 잡음 |

## 8. VPN과 무선 채널

**IPsec**: VPN의 터널링 프로토콜로 OSI **3계층**에서 동작하며 **전송 모드**(IP 페이로드만 암호화·캡슐화)와 **터널 모드**(원본 IP 패킷 전체를 새 IP 헤더로 캡슐화)를 씁니다. PPTP와 L2TP는 2계층, SSL/TLS는 상위 계층입니다.

**무선 채널**: 번호로 구분하고, 주파수 대역이 겹치면 간섭이 생기며, 장비가 자동 선택하거나 관리자가 수동 지정합니다. 무선 호스트는 AP와 통신할 때 채널을 이용합니다.

## 9. 시험 직전 점검

> - 단위: 물리 비트, 데이터링크 프레임, 네트워크 패킷, 전송 세그먼트.
> - 압축·암호화는 표현 계층. 세션은 대화 제어·동기화. 전송은 흐름 제어와 오류 없는 전송.
> - 프로토콜 3요소는 구문, 의미, 타이밍.
> - Go-back-N은 오류 난 블록부터 모두, Selective는 오류 난 것만, Adaptive는 프레임 길이 변경.
> - FEC는 자동 재전송 기법이 아님.
> - TDM은 빈 슬롯도 할당, WDM은 광 파장 다중화.
> - IPsec은 3계층, 전송·터널 모드.
