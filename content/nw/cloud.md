# 가상화·클라우드·SDN

<div class="summary">

- **클라우드 배포 모델**: public, private, hybrid(그리고 community). **on-premises는 배포 모델이 아닙니다.**
- **클라우드 특징**: 필요한 만큼 사용, 자원의 동적 할당, 미터링으로 사용량 제어. 자원은 **다중 임차인(multi-tenant)** 모델의 풀로 운영합니다(단일 임차인이 아님).
- **SDN**은 제어 평면과 데이터 평면을 **분리**해 소프트웨어로 중앙 제어합니다. **NFV**는 네트워크 기능(방화벽, 라우터 등)을 **소프트웨어(VNF)** 로 가상화합니다.
- **서버리스**는 서버를 직접 관리하지 않고 실행한 만큼 과금하며 자동 확장·축소됩니다.
- **IDC**는 서버를 맡기는 데이터 센터, **포그 컴퓨팅**은 데이터 발생 지점 가까이에서 처리합니다.

</div>

## 1. 클라우드 컴퓨팅

### 특징

| 특징 | 설명 |
|---|---|
| 온디맨드 | 사용자는 필요한 만큼의 서버, 네트워크, 저장장치 같은 컴퓨팅 능력을 활용 |
| 동적 할당 | 사용자 요구에 따라 물리 자원과 가상 자원이 **동적으로 할당/재할당** |
| 미터링 | 서비스 형태에 맞는 미터링으로 자원 사용을 자동으로 제어·최적화 |
| **자원 풀** | 다수의 사용자를 지원하려고 **다중 임차인(multi-tenant)** 모델의 자원 풀로 운영 |
| 단점 | 통신 환경에 따라 서비스에 영향을 받고, 개별 정보가 물리적으로 어디에 있는지 알기 어려움 |

> **함정** "단일 임차인(single-tenant) 모델의 자원 풀"은 클라우드의 특징으로 틀립니다. 클라우드는 여러 사용자가 자원을 공유하는 **다중 임차인** 모델입니다.

### 배포 모델

| 모델 | 설명 |
|---|---|
| **공용(public)** | 아마존 웹 서비스처럼 **외부 제공자**가 관리, 인터넷으로 접근 |
| **사설(private)** | 특정 조직(회사) **내부**용으로 서버, 저장장치, 네트워크, 응용을 묶음 |
| **하이브리드(hybrid)** | 공용과 사설을 혼용. 사설을 구축해 쓰는 기업이 일부를 공용 업체에서 제공받고 사설과 연동 |

> **함정** 사설 클라우드를 "회사 내·외부의 모든 이용자가 공유"한다고 하면 틀립니다. **on-premises**는 배포 위치를 뜻하는 말이지 위 세 가지 배포 모델에 들어가지 않습니다.

### 서버리스 컴퓨팅

| 사실 | 내용 |
|---|---|
| 관리 | 클라우드 제공자가 인프라를 관리하므로 **직접적인 서버 관리가 필요 없음** |
| 과금 | 코드가 실행되는 시점에 **사용한 자원량**에 따라 요금 계산 |
| 확장 | 필요에 따라 **오토스케일링** |
| 틀린 설명 | 사용자가 서버 인스턴스 프로비저닝과 **OS 패치를 직접 관리**한다 |

## 2. SDN과 NFV

| | SDN | NFV |
|---|---|---|
| 핵심 | **제어 평면과 데이터 평면 분리**, 중앙 컨트롤러가 프로그래밍으로 제어 | 방화벽, 라우터, 로드 밸런서 같은 **네트워크 기능을 소프트웨어(VNF)로 가상화** |
| 제어 | **하드웨어가 아닌 소프트웨어**로 제어하는 네트워킹 기술 | 필요에 따라 유연하게 배포·확장 |
| 구성 | | **NFVI**: 물리적 H/W 자원, 가상화 지원 기능, VNF 실행 지원 기능 제공 |
| 목적 | 구조적 유연성과 개방성으로 트래픽 변화에 대응 | 복잡한 네트워크의 관리 용이성, 관리 비용 절감, 민첩성 |

> **함정** NFV를 "소프트웨어가 아닌 하드웨어로 제어되는 네트워킹 기술"이라고 하면 틀립니다(이것은 SDN을 뒤집은 오답). 네트워크 기능마다 전용 하드웨어가 필수라는 설명이나 물리 서버 없이 운영한다는 설명도 틀립니다.

SDS는 스토리지, SNMP는 관리 프로토콜, CLI는 명령행 인터페이스이므로 SDN의 보기 중 오답입니다. WMN은 무선 메시, VPN은 가상 사설망, CDN은 콘텐츠 전송망입니다.

## 3. 컴퓨팅 구조와 데이터 센터

| 용어 | 설명 |
|---|---|
| **IDC (Internet Data Center)** | 서버를 맡겨 **전용회선과 안정적인 전력 공급**, 냉각·항온항습을 받음. 서버 증설로 공간·전기·발열 비용이 부담될 때 이용 |
| **포그 컴퓨팅(Fog)** | 현장에서 발생한 데이터를 원거리 데이터 센터로 보내는 대신 **발생 지점 주변**에서 선별 분석·활용 |
| 그리드 컴퓨팅 | 분산된 자원을 묶어 사용 |
| 병렬/직렬 컴퓨팅 | 처리 방식 구분 |
| IPS, IDS | 침입 방지/탐지 시스템 |

## 4. 시험 직전 점검

> - 배포 모델: public, private, hybrid. on-premises는 아님.
> - 클라우드는 다중 임차인 자원 풀.
> - SDN은 제어 평면과 데이터 평면 분리, NFV는 VNF로 가상화.
> - 서버리스는 OS 패치를 사용자가 관리하지 않음.
> - 포그는 현장 처리, IDC는 서버 위탁.

## 5. OX 점검

| 문장 | 답 | 이유 |
|---|---|---|
| on-premises는 클라우드 배포 모델이다. | X | public, private, hybrid가 배포 모델입니다. |
| 클라우드는 단일 임차인 모델의 자원 풀을 쓴다. | X | 다중 임차인입니다. |
| SDN은 제어 평면과 데이터 평면을 분리한다. | O | |
| NFV는 네트워크 기능을 하드웨어 전용 장비로만 구현한다. | X | 소프트웨어(VNF)로 가상화합니다. |
| 서버리스에서는 사용자가 OS 패치를 직접 관리한다. | X | 제공자가 인프라를 관리합니다. |
| 포그 컴퓨팅은 데이터 발생 지점 가까이에서 처리한다. | O | |
| 하이브리드 클라우드는 공용과 사설을 함께 쓴다. | O | |
| IDC는 서버 운영 공간과 전용회선, 전력을 제공한다. | O | |
