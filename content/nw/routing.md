# 라우팅

<div class="summary">

- **RIP**: 거리 벡터 방식, 메트릭은 **Hop Count만** 사용, 업데이트 주기 30초, 소규모에 적합.
- **정적 라우팅**: 관리자가 직접 경로 지정. 라우터 부하가 적고 메모리 관리에 유리하며 **우선순위가 높습니다**.
- **동적 라우팅**: 라우팅 알고리즘으로 자동 경로 설정, 환경 변화에 능동적으로 대처.
- **거리 벡터** 계열: IGRP, RIP(Bellman-Ford). **OSPF는 링크 스테이트**(Dijkstra)라 거리 벡터가 아닙니다.

</div>

## 1. RIP

| 사실 | 내용 |
|---|---|
| 방식 | **거리 벡터** |
| 메트릭 | **Hop Count만** 고려 |
| 업데이트 | 기본 라우팅 업데이트 주기 **30초** (1초가 아님) |
| 적합한 규모 | 소규모 (대규모에서 주로 쓰인다는 설명은 틀림) |
| 약점 | 변화가 느리고 라우팅 루프가 생기기 쉬움 |

> **함정** 링크 상태 알고리즘으로 변화가 빠르다는 설명은 RIP이 아니라 OSPF의 설명입니다.

## 2. 정적 라우팅과 동적 라우팅

| | 정적 라우팅 | 동적 라우팅 |
|---|---|---|
| 경로 설정 | 관리자가 수동으로 | 라우터 간 프로토콜과 알고리즘으로 자동 |
| 부하 | 라우터에 **부하가 적고 메모리 관리에 유리** | 부하가 더 큼 |
| 환경 변화 | 대응하지 못함 | 능동적으로 대처 |
| 우선순위 | **높음** | 낮음 |
| 적합한 환경 | 소규모, 변화 적은 망 | 다수의 네트워크가 수시로 변하는 환경 |

## 3. 거리 벡터와 링크 상태

**거리 벡터**: 네트워크 변화 시 해당 정보를 **인접 라우터에 정기적으로** 전달하고 인접 라우터가 라우팅 테이블을 갱신합니다. 최단 경로는 **Bellman-Ford** 알고리즘 기반입니다. 이 설명에 해당하는 프로토콜은 IGRP, RIP, BGP 등이고, **OSPF는 해당하지 않습니다**.

**링크 상태**: 자신의 링크 상태를 모든 라우터에 알리고 각 라우터가 **Dijkstra** 알고리즘으로 최단 경로를 계산합니다(OSPF).

## 4. 시험 직전 점검

> - RIP = 거리 벡터, Hop Count, 30초.
> - OSPF = 링크 스테이트, Dijkstra. 거리 벡터가 아님.
> - 정적 라우팅은 부하가 적고 우선순위가 높음.
